このサイト（kokinn.com）を、AWS上の WordPress から Cloudflare に移しました。月々のサーバー代を下げつつ、記事はそのまま残す、というのが目的です。

「移管」と聞くと難しそうに見えますが、今回やったことは大きく分けると次の5つです。

1. WordPress の中身を全部バックアップする
2. 記事を Markdown にして、静的サイトにする
3. ドメインの向き先を Cloudflare に変える
4. GitHub に上げて、自動で公開する
5. もう使わない AWS を止める

この記事では、その順番どおりに、実際にやったことを書きます。

## 移す前の状態

もともとこのサイトは、だいたいこんな構成でした。

- ドメインは **お名前.com**（.com。期限は 2028年8月12日）
- サーバーは **AWS EC2**（東京、t2.micro、Bitnami WordPress）
- テーマは AFFINGER5
- 記事は 452本、画像は WordPress のアップロードフォルダに保存
- 広告は Google AdSense とアフィリエイト

AWS の請求は、だいたい **月18ドル前後** 出ていました。内訳のイメージはこんな感じです。

- EC2 本体：約11ドル
- 公開IPv4（VPC）：約3.72ドル
- ディスク（EBS）：約1.45ドル
- ドメインの名前解決（Route 53）：約0.62ドル

「WordPress を Cloudflare 上でも動かす」方法もあります。ただ今回は、**記事だけ移して WordPress はやめる**ことにしました。理由は単純で、サーバーを常時起動しておく必要がなくなるからです。

最終的な構成はこうなりました。

- 記事：Markdown
- サイト生成：Astro（静的サイト）
- 保管：GitHub
- 公開：Cloudflare Workers
- ドメイン：お名前.comのまま（Cloudflare Registrar には移さない）

ドメインまで Cloudflare に移すと、年額は少し安くなることがあります。ただ日本のサポートや円建ての管理を考えると、今回はお名前.comのままにしました。差は年数百円くらいです。

## 1. まず WordPress を丸ごとバックアップする

移す前に、いちばん大事なのはバックアップです。サーバーを止めてから「記事が残っていない」では終わりません。

今回は **All-in-One WP Migration** で、サイト全体の `.wpress` ファイルを書き出しました。容量はだいたい 942MB でした。

このファイルの中には、記事のデータベース、メディア、プラグイン情報が入っています。静的サイトにする場合、あとで使うのは主に次の2つです。

- 記事本文（データベース）
- 画像などのアップロードファイル

ポイントは、**AWS を止める前に、手元のPCへ必ず保存すること**です。EC2 を消すと、サーバー上のファイルは戻りません。

## 2. 記事を Markdown に変換する

`.wpress` からデータベースを取り出して、公開中の記事だけ Markdown にしました。

新しいサイトでは、URL をできるだけ崩さないようにしています。

- 旧：`https://kokinn.com/?p=2832`
- 新：`https://kokinn.com/posts/2832`

記事IDをそのままパスに使うと、検索エンジンや被リンクのダメージが小さくなります。さらに、古い `?p=` つきのURLが来たときは、新しいURLへ飛ばす処理も入れています。

WordPress の固定ページも移しました。プライバシーポリシー、英会話スクール、プログラミングスクールの案内です。カテゴリも、今まで使っていた名前を残しています。

ここで1つ、はまりやすい点があります。AFFINGER の飾り枠です。

WordPress では `[st-mybox]...[/st-mybox]` のようなショートコードが、見た目の見出し枠になっていました。静的サイトではそのコードを解釈しないので、最初はそのまま文字として出てしまいました。今回は、その枠を普通の見出しデザインに変換しています。

Amazon の商品タグやキャプションも、同じように変換が必要でした。テーマ依存の部品は、移したあとに必ず1ページ見て確認した方がいいです。

## 3. 画像を HTTPS で出せるようにする

旧サイトは HTTP で動いていました。新しいサイトは HTTPS です。

このままだと、ブラウザが「混合コンテンツ」として画像を止めます。画面には記事だけ出て、画像が全部欠けた状態になります。

対応はシンプルです。

- WordPress のアップロード画像を、新しいサイトの `public/wp-content/uploads/` にコピーする
- 記事中の画像URLを、`http://kokinn.com/wp-content/uploads/...` から `/wp-content/uploads/...` に書き換える

今回は画像が約777ファイル、合計約187MB ありました。数は多いですが、一度コピーしてしまえば、あとは静的ファイルとして配信できます。

## 4. サイトの器を作る

中身が Markdown になったら、それを表示する器が必要です。今回は Astro で静的サイトにしました。

最低限つくったものは次のとおりです。

- トップページ（最新記事）
- 記事ページ `/posts/記事ID`
- カテゴリ一覧とカテゴリ別ページ
- 固定ページ
- 広告用の `ads.txt`
- 古い `?p=` URL のリダイレクト

広告は、最初はページのあちこちへ枠を置いていました。ただ自動広告と全画面広告が重なると、記事が読みにくくなります。いまは **自動広告はオフ**、記事の末尾に広告枠を1つ、という形にしています。

AdSense のパブリッシャーIDは、WordPress 時代と同じものを使っています。サイトの見た目が変わっても、ads.txt と広告コードさえ正しければ、審査済みのサイトとして続けられます。

## 5. GitHub に上げて、Cloudflare で公開する

ローカルでサイトができたあと、GitHub の公開リポジトリに置きました。

- リポジトリ：https://github.com/kokinnwakashuu/kokinn-com
- ブランチ：`main`

公開の流れはこうです。

1. `npm run build` で静的ファイルを作る
2. `npx wrangler deploy` で Cloudflare Workers に出す
3. GitHub の `main` に push すると、同じことを自動でやる

Cloudflare 側では、次を用意します。

- ドメイン `kokinn.com` のゾーンを追加する
- ネームサーバーを Cloudflare のものに変える（今回は `alina.ns.cloudflare.com` と `tom.ns.cloudflare.com`）
- Worker を作る（今回の名前は `kokinn-com`）
- カスタムドメインに `kokinn.com` と `www.kokinn.com` を付ける

お名前.com 側でやることは、ネームサーバーの変更だけです。ドメインの契約そのものは、お名前.com に残したままです。

反映には時間がかかることがあります。焦って AWS を消さないでください。先に、

- https://kokinn.com/
- https://www.kokinn.com/

の両方が、新しいサイトを返すことを確認します。確認用の Workers プレビューURLもありますが、本番は独自ドメインで見て判断した方が安心です。

## 6. 新しいサイトが見えたら、AWS を止める

新しいサイトが独自ドメインで見えてから、旧サーバーを止めます。順番を逆にすると、サイトが途切れる時間が発生します。

今回止めたものは次のとおりです。

- EC2 インスタンス（Bitnami WordPress）を終了
- 残っていた EBS ボリュームを削除
- Route 53 のホストゾーンを削除

ここで注意です。EC2 を止めても、**その月の使った日数分は請求に残ります**。止まるのは「これ以降の時間課金」です。本当に止まったかどうかは、1〜2日あとの Cost Explorer の日次グラフで見た方が確実です。

ディスクや Elastic IP、ホストゾーンが残っていると、少額でも課金が続きます。インスタンスを消したあとに、ボリュームと Route 53 も確認してください。

## 移してから直したこと

公開した直後に、いくつか見た目と広告の問題が出ました。静的サイト化あるある、という感じです。

**自己紹介の飾り枠**  
AFFINGER のショートコードが生テキストで出ていました。見出し枠に変換して直しています。

**サイト名**  
デザインを整える過程で短い名前に見えてしまったので、元のサイト名「自作ゲームの世界を広げることで技術力を高める企画サイト」に戻しました。AdSense やアフィリエイトに紐づく名前は、むやみに変えない方がいいです。

**変な広告**  
「続きへ進むにはこちら」のような全画面広告が出て、関係ないサイトへ飛ぶことがありました。AdSense の自動広告・全画面広告・Multiplex が原因になりやすいです。いまは自動広告オフ、記事下のバナー1枠にしています。

**プロフィール**  
学歴・資格・書籍（76冊）、Kaggle（https://www.kaggle.com/kokinnwakashuu）も、移したタイミングで最新に更新しました。

## 今回の結論

WordPress を Cloudflare に「丸ごと載せる」のではなく、**記事を静的サイトにして Cloudflare で配る**方が、今回の目的には合っていました。

残るコストは、お名前.com のドメイン代が中心です。AWS の月18ドルは、インスタンスと付属リソースを消せば止まります。

同じことをするなら、順番だけ守ってください。

1. `.wpress` を手元に保存する
2. 新しいサイトを別の場所で完成させる
3. 独自ドメインで新しいサイトが見えることを確認する
4. それから AWS を止める

この順番を守れば、「移したつもりがサイトが消えた」にはなりにくいです。
