このサイトを、AWS 上の WordPress から Cloudflare に移しました。サーバー代を下げつつ、記事はそのまま残す、というのが目的です。AWS ではだいたい **月18ドル** かかっていたので、サーバーを止めればその分が節約になります。いまの公開先である Cloudflare の維持費は、無料プランで **0円** です。

WordPress を Cloudflare 上でも動かす方法もあります。ただ今回は、**記事だけ移して WordPress はやめる**ことにしました。サーバーを常時起動しておく必要がなくなるからです。

いまの構成はこうです。

- 記事：Markdown
- サイト：Astro
- 保管：GitHub
- 公開：Cloudflare（無料プラン。維持費0円）
- ドメイン：お名前.comのまま

ドメインまで Cloudflare に移すと、年額は少し安くなることがあります。ただ差は年数百円くらいで、日本のサポートや円建ての管理を考えると、今回はお名前.comのままにしました。

今回の作業は、Cursor に相談しながら進めました。構成の選び方、記事の移し方、ドメインの向き先、公開後の見た目や広告の直し方まで、わからないところを聞きつつ作業しています。全部を丸投げしたというより、方針を決めて、具体的な手順を確認しながら進めた感じです。

やったことは、この順番です。

## 1. バックアップを取る

移す前に、サイトの中身を手元へ保存します。サーバーを止めてから「記事が残っていない」では終わりです。

今回は WordPress の移行用プラグインで、記事と画像ごと書き出しました。AWS を止める前に、必ず自分の PC へ保存してください。

## 2. 記事を Markdown に変換する

書き出したデータから、公開中の記事を Markdown にしました。URL はできるだけ崩さないようにしています。

- 旧：`/?p=記事ID`
- 新：`/posts/記事ID`

古い `?p=` つきのURLが来たときは、新しいURLへ飛ばすようにしています。固定ページやカテゴリ名も、そのまま残しました。

テーマ独自の飾り枠は、静的サイトだとただの文字になって出ることがあります。移したあとに、自己紹介など目立つページは一度見た方がいいです。

## 3. 画像も一緒に移す

旧サイトが HTTP のままだと、新しい HTTPS のサイトで画像が欠けます。画像ファイルも一緒に移して、記事中のURLをサイト内のパスに直しました。

## 4. GitHub に上げて、Cloudflare で公開する

サイトの器は Astro で作り、GitHub に置いて Cloudflare から公開しています。お名前.com 側でやったことは、ネームサーバーを Cloudflare 向けに変えたくらいです。ドメインの契約そのものは移していません。日本の窓口が使える方が安心だった、というのが大きいです。

焦って旧サーバーを消さないでください。先に、自分のドメインで新しいサイトが見えることを確認します。

## 5. 新しいサイトが見えたら、AWS を止める

独自ドメインで新しいサイトが見えてから、旧サーバーを止めます。順番を逆にすると、サイトが途切れる時間が発生します。

仮想サーバー本体だけでなく、ディスクや DNS の設定が残っていると、少額でも課金が続くことがあります。止めたあとに、使っていないリソースが残っていないかも確認してください。その月の使った日数分は請求に残るので、完全にゼロになるのは少し先です。

## 移してから直したこと

公開した直後に、いくつか見た目と広告の問題が出ました。静的サイト化あるある、という感じです。

**自己紹介の飾り枠**  
旧テーマのショートコードが生テキストで出ていました。見出し枠に変換して直しています。

**サイト名**  
デザインを整える過程で短い名前に見えてしまったので、元のサイト名に戻しました。広告やアフィリエイトに紐づく名前は、むやみに変えない方がいいです。

**変な広告**  
「続きへ進むにはこちら」のような全画面広告が出て、関係ないサイトへ飛ぶことがありました。自動広告や全画面広告が原因になりやすいです。いまは自動広告オフ、記事下のバナー1枠にしています。

**プロフィール**  
学歴・資格・書籍、Kaggle の情報も、移したタイミングで最新に更新しました。

## 今回の結論

WordPress を Cloudflare に「丸ごと載せる」のではなく、**記事を静的サイトにして Cloudflare で配る**方が、今回の目的には合っていました。Cloudflare 側の維持費は0円で、残るコストはお名前.com のドメイン代が中心です。AWS の月18ドルは、使っていないサーバーを消せば止まります。Cursor に相談しながらでも、順番さえ守れば個人サイトの移管は現実的です。

同じことをするなら、順番だけ守ってください。

1. バックアップを手元に保存する
2. 新しいサイトを別の場所で完成させる
3. 独自ドメインで新しいサイトが見えることを確認する
4. それから旧サーバーを止める

この順番を守れば、「移したつもりがサイトが消えた」にはなりにくいです。
